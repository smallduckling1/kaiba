# Kaiba

Standalone open-source compiler infrastructure in Rust. Not a language; a
toolchain: `.ll`/`.llcr` ingestion -> llcr SSA optimizer -> x86_64/AArch64 backend.

## Crates
- `llcr`: the IR (types, arena-based CFG, parser/printer, verifier, passes, pass manager).
- `kaiba-ll`: LLVM IR (`.ll`) frontend. Handles what clang emits for integer/pointer C at -O0..-O2
  (phis, switch, GEP incl. constant expressions, varargs calls, pointer tables in global initializers,
  memcpy/memset/ctpop/bswap/rotate/with.overflow/float-math intrinsics, ...).
- `kaiba-mir`: target-independent backend core: machine IR, llcr -> MIR instruction selection
  (incl. out-of-SSA), linear-scan register allocation (generic over the register file), data emission.
- `kaiba-x86`: x86_64 System V (Linux) assembly emitter. Integers, pointers, scalar f32/f64 (SSE), small-aggregate returns, `sret`, `byval`.
- `kaiba-a64`: AArch64 AAPCS64 (Linux) assembly emitter. Same feature set (minus `byval`, which AAPCS64 doesn't use).
- `kaiba`: the command-line driver.

## Usage
```bash
cargo run -p kaiba -- opt -O1 input.llcr          # optimize, print llcr (input may also be clang's .ll)
cargo run -p kaiba -- opt --passes=mem2reg,dce -  # explicit pipeline from stdin
cargo run -p kaiba -- asm input.llcr              # assembly (x86_64 Intel syntax by default)
cargo run -p kaiba -- asm --target=aarch64 input.ll   # AArch64 (also inferred from the module's target triple)
cargo run -p kaiba -- build -o prog input.llcr main.c   # compile + link via system cc
cargo run -p kaiba -- verify input.llcr
cargo run -p kaiba -- passes
```
Passes: `inline` (module; also drops unreferenced internal functions), `mem2reg`, `simplifycfg`,
`constfold`, `licm`, `dce`. `-O1` runs all of them.

## Testing
`cargo test` runs unit tests plus end-to-end tests that need external tools; each test skips
itself if its tools are missing:
- `gcc` (x86_64) and `clang` (to generate `.ll` from C for differential tests),
- `aarch64-linux-gnu-gcc` + `qemu-aarch64` (AArch64 cross toolchain and user-mode emulator;
  on Debian/Ubuntu: `gcc-aarch64-linux-gnu libc6-dev-arm64-cross qemu-user`).
Differential tests compile C with clang, push the `.ll` through Kaiba, and require output identical
to gcc's for the same target.

## Real-world check: zlib
`tools/zlib-check.sh [x86|a64|both]` downloads zlib 1.3.1, compiles it with clang -> Kaiba (x86_64 and/or AArch64),
and requires (1) zlib's own `example.c` and (2) `tools/zlib-stress.c`, which compresses 1 MB buffers at every level and
strategy, to produce output byte-identical to a gcc-built zlib. It has already found real bugs (see git history of
`regalloc.rs`: dead definitions must not receive registers).
